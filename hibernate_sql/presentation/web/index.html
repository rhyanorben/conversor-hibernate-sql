Hibernate → PostgreSQL

Cole a SQL e os logs de binding. Gere a query com os valores preenchidos para testar no PostgreSQL.

Como usar

Cole os logs ou arraste um arquivo .log ou .txt para este painel para converter automaticamente em SQL sem comando adicional.

Logs misturados são separados automaticamente quando a thread está identificada nos registros de SQL e binding. Os erros indicam a query, a linha e o parâmetro envolvidos, quando disponíveis.

Os logs são enviados ao servidor desta aplicação para conversão. Opções de EXPLAIN com ANALYZE executam a instrução quando rodadas no PostgreSQL.

Gerar logs no Spring Boot

No Hibernate 6, use DEBUG para registrar a SQL e TRACE para registrar os valores dos parâmetros. Escolha o formato usado pela sua aplicação.

  1. Edite a configuração do perfil ativo em src/main/resources ou no local definido pelo projeto. Se os níveis forem definidos em XML, aplique também spring.jpa.show-sql=true e spring.jpa.properties.hibernate.format_sql=true no arquivo da aplicação.
  2. Reinicie a aplicação e execute a operação que consulta o banco. Copie os registros de org.hibernate.SQL e as linhas binding parameter correspondentes. Com show-sql ativo, a mesma SQL pode aparecer também como Hibernate:. Em logs intercalados, copie os registros com a thread.
  3. Se usar um formato de log personalizado, mantenha a saída em texto, com o nome completo do logger e a thread entre colchetes. Confira se os filtros do destino permitem DEBUG e TRACE.
Exemplo do log esperado 
2026-11-11T10:00:00.000 DEBUG [worker-1] org.hibernate.SQL : select * from minha_tabela where minha_coluna = ?
2026-11-11T10:00:00.001 TRACE [worker-1] org.hibernate.orm.jdbc.bind : binding parameter (1:INTEGER) <- [123]

Os exemplos são para os bindings do Hibernate 6. O Hibernate 5 usa o formato BasicBinder, fora da compatibilidade atual do conversor.

Use em desenvolvimento: os parâmetros podem expor dados sensíveis e TRACE aumenta o volume dos logs. Remova ou desative esses níveis após o diagnóstico.
